# Сбор карт ISW

> С пользователем — только на русском: ответы, вопросы, кнопки, окошко итога, отчёты.

## Вкладку ISW никогда не закрывать
Сайт капризный (Cloudflare, проверка «не робот»), а прошедшая проверку вкладка — единственный рабочий доступ.
**Никогда не закрывать вкладку understandingwar.org** (не вызывать `tabs_close_mcp` для неё) — ни после сбора,
ни в конце задачи, даже если общие правила браузера велят закрывать свои вкладки. Переходить внутри неё можно.
В начале работы — `tabs_context_mcp`, найти уже открытую вкладку ISW и работать в ней, а не открывать новую.

## Ограничения сайта
- understandingwar.org за Cloudflare. curl/requests → 403. Работаем только в Chrome пользователя (Claude in Chrome); во встроенном браузере капча не проходит.
- Если заголовок вкладки «Один момент…» / «Just a moment…» — попросить пользователя нажать галочку в панели браузера. Самому капчу не проходить.

## Диапазон и папка сессии
`python scripts/maps.py next` → папка сессии (квартал сегодняшней даты, напр. `26.10`) и строка запуска
`iswRun('<день после последнего собранного>', '<сегодня>', '<сессия>')`. Все дни диапазона кладутся в одну папку
сессии, даже если они из разных кварталов. Никогда не раскладывать по кварталам дат карт.
В папке новой сессии уже лежит отправная точка (по последней карте каждого направления из прошлой сессии,
с оригиналами в `_raw`) — новые карты докладываются в эти папки; `crop` уже обрезанные не трогает.

## Порт приёмника
Приёмник пишет только в `<YY.MM>/(_raw|_manifest|_collect|_youtube…)/` и только с вкладок understandingwar.org и
studio.youtube.com (чужой сайт → 403, другой путь → 400); недокачанное тело не сохраняет.
Наш порт — **18765**. 8765 занимают другие сессии Claude (проект youtube/video) со своими приёмниками: если
сборщик пишет не в наш сервер, он может испортить чужие файлы. Перед запуском проверить, что порт слушает наш
`scripts/receiver.py` (`Get-NetTCPConnection -LocalPort 18765` → командная строка процесса). Чужие процессы не трогать.

## Порядок
1. Запустить приёмник в фоне: `python scripts/receiver.py` (порт 18765). Проверка: `GET http://127.0.0.1:18765/ping`.
2. Для каждого дня периода открыть статью «Russian Offensive Campaign Assessment, <Month> <D>, <YYYY>».
   Только тема Россия–Украина. Если статьи за день нет (404) — манифест со `status: 404`. Другие ответы (429/5xx), день без карт по теме или с
   ошибкой картинки — манифест НЕ пишется (день перекачается), дата попадает в `incomplete` в `status.json`;
   `maps.py next` показывает дни без манифеста (дыры) — перекачать их до обрезки.
   URL статьи: `https://understandingwar.org/research/russia-ukraine/russian-offensive-campaign-assessment-<month>-<d>-<yyyy>/`
   (month строчными по-английски, день без нуля). Проверять существование fetch-ем из вкладки сайта: 404 = отчёта нет
   (например, 1 января 2026 — праздник). Поиск сайта и `/wp-json` бесполезны (поиск не находит, API → 403).
3. Собрать картинки карт: fetch HTML статьи, DOMParser, `img` внутри `a[href*="/map/"]`.
   - Ссылка ведёт на страницу карты `/map/assessed-control-of-terrain-in-the-<направление>-<month>-<d>-<yyyy>-at-130-pm-et/`,
     её `<h1>` = точная шапка: `Assessed Control of Terrain in the Kherson Direction, January 2, 2026 at 1:30 PM ET`.
   - `src` превью: `/wp-content/uploads/<YYYY>/<MM>/<Имя>-<Month>-<D>-<YYYY>.webp`.
     Рядом лежит `.png` того же разрешения без потерь — **качаем .png** (jpg/scaled → 403).
     Пример: 2 января 2026, Kherson-Direction → 1795×2244.
   - В статье 2 января 2026 было 13 карт: Russo-Ukrainian-War (общая), Sumy-Direction, Kharkiv-Direction,
     Luhansk-Oblast, Borova-Lyman-Direction, Lyman-Tactical-Area, Donetsk-Oblast,
     Kostyantynivka-Druzhkivka-Tactical-Area, Kostyantynivka, Pokrovsk-Direction, Zaporizhia-Oblast,
     Zaporizhzhia-City-Direction, Kherson-Direction. Последняя `img` (Babel Street logo) — не карта.
   - Работать в Chrome пользователя (Claude in Chrome): там Cloudflare не мешает.
4. Определить направление и дату каждой карты:
   - имя папки = имя файла без даты и без `-Direction`: `Kherson-Direction-January-2-2026` → `Kherson`,
     `Russo-Ukrainian-War-…` → `Overview`, `Kostyantynivka-Druzhkivka-Tactical-Area` → как есть;
   - если неоднозначно — посмотреть шапку карты глазами (`Assessed Control of Terrain in the <X> Direction`, дата).
   - Дата в имени файла = дата из шапки карты, не дата статьи (обычно совпадают; расхождение записать).
   - Нерелевантные картинки (инфографика, не карты контроля территории) — пропускать, но перечислить пользователю.
5. Скачивать сборщиком `scripts/collect.js` (он делает шаги 2–4 сам):
   ```js
   eval(await (await fetch('http://127.0.0.1:18765/collect.js')).text());
   window.iswDone = null;
   iswCollect(2026, 1, 7, '26.10').then(r => window.iswDone = r);   // в фоне: день идёт ~40 с
   // потом опрашивать: window.iswDone && iswSummary(window.iswDone)
   ```
   - Диапазон: `iswRun('2026-01-08', '2026-10-19', '26.10')` в фоне вкладки (не await!). Готовые дни (есть манифест) пропускаются,
     поэтому после остановки просто запустить снова. В конце пишет `<сессия>/_collect/status.json`. Прогресс: `iswStatus()`.
   - **Темп (просьба пользователя, сайт не любит спам):** страница статьи (= 1 день) не чаще раза в 10 с,
     картинка не чаще раза в 2 с (`ISW_PAGE_DELAY_MS`, `ISW_IMAGE_DELAY_MS`). День ≈ 35 с, квартал дат ≈ 1 ч.
     Отдельные страницы `/map/…` не грузим — направление и дата есть в имени файла.
   - Паузы — через `/sleep` приёмника: таймеры фоновой вкладки Chrome троттлятся до раза в минуту.
   - Повторы внутри `iswRun`: сетевой сбой («Failed to fetch») → пауза 60 с и повтор дня; 403 Cloudflare → статья
     открывается в скрытом iframe (допуск обычно обновляется сам) и день повторяется; до 4 попыток.
   - Картинка: сначала `.png`, запасной — исходный файл из статьи (бывают `.gif`, `-scaled.webp`). Блокировка
     Cloudflare = две карты направлений подряд не скачались. (Раньше 403 на подставленный `.webp` у GIF-карты
     ложно считался блокировкой и останавливал сбор.)
   - Декодированные картинки (`createImageBitmap`) обязательно `close()` — иначе утечка ~16 МБ на карту и падение вкладки.
   - **Зависание**: Chrome может выгрузить/заморозить фоновую вкладку (у неё меняется tabId, переменные пропадают,
     статус не пишется). Поэтому каждый запрос с тайм-аутом (`iswFetch`), в начале прогона и после каждого дня пишется пульс
     `<сессия>/_collect/heartbeat.txt`. Наблюдатель (фоновая команда) ждёт status.json ИЛИ пульс старше 10 мин:
     `S=26.10/_collect; while true; do [ -f $S/status.json ] && break; age=$(( $(date +%s) - $(stat -c %Y $S/heartbeat.txt) )); [ $age -gt 600 ] && break; sleep 60; done`
     При зависании: `tabs_context_mcp` (новый tabId!), перейти вкладкой на статью следующего дня, загрузить сборщик, `iswRun`.
   - iframe-обновление на практике не спасает. Если остановился (`stopped` в статусе): перейти вкладкой на статью дня
     остановки — проверка обычно проходит сама за пару секунд (на практике каждые ~20–30 мин; при этом
     если висит галочка — попросить пользователя), загрузить сборщик заново и снова `iswRun`.
   - Названия папок у ISW со временем меняются (Kharkiv → Kharkiv-Oblast, Eastern-Zaporizhia → Eastern-Zaporizhia-Oblast,
     Pokrovsk → Pokrovsk-Agglomeration …) — при сборе не склеивать, это решается на проверке с пользователем.
     Перед перезапуском переименовать `<сессия>/_collect/status.json` → `status_runN.json`.
   - 404 за последние 3 дня в манифест не пишется: статью могут выложить позже.
   - Chrome один раз спрашивает «доступ к локальной сети» для understandingwar.org — пользователь разрешает.
   - Не по теме — **не скачиваются**, только записываются в манифест (`off_topic: true`); `_skipped` не хранить (пользователь). В статьях бывают тематические карты (захват судна, пожары NASA FIRMS, удары по НПЗ,
     BM-35, «Phase Zero» в Европе, Новороссия). Карта направления — только если slug страницы `/map/…` начинается с
     `assessed-control-of-terrain` (бывает опечатка `ssessed`), `control-of-terrain`, `russo-ukrainian-war-`
     или с короткого (≤4 слов) имени самой карты (`eastern-dnipropetrovsk-oblast-april-26-…`).
   - Манифест дня пишется в `<сессия>/_manifest/<yyyy-mm-dd>.json`.
   - Возвращать в чат только `iswSummary(...)`: длинные URL в ответе инструмента иногда маскируются.
